# U3 — Idempotent order submission

## Purpose
Incremental-value unit: retries are safe. This is the unit the walking
skeleton builds through LLD → implementation → verification (doc 12 §1).

## Summary (S1)
Submit-with-retry semantics on Order Service per ADR-014: same
Idempotency-Key returns the original order id and creates at most one order.
Covers FS-014. Demoable: double-tap submit on a flaky network, one order.

## Scope & Non-scope
Submission idempotency only. Non-goals: notifications dedup (FS-022, C-4),
partial fulfilment (U2).

## Value statement
The user can resubmit an order after a network failure and still see exactly
one order.

## Acceptance criteria
### AC-U3-1 — At most one order per key
derives_from: [FS-014]
statement: Resubmitting the same payload with the same Idempotency-Key within 24h creates at most one order.

### AC-U3-2 — Original id returned
derives_from: [FS-020]
statement: The retried response returns the order id created by the first accepted submission.
